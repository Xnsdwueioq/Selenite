# Selenite

Приложение для фокус-сессий на SwiftUI, iOS 18+. Swift 6;
локальный пакет `FocusCore` требует Swift tools 6.4.

## Архитектура

- Следуй устройству соседнего кода. Не вводи новую архитектуру, слои,
  протоколы или зависимости без конкретной необходимости для задачи.
- `Packages/MyLibrary/Sources/FocusCore` – модели, переходы состояний,
  расписание и форматирование таймера. Сохраняй ядро детерминированным:
  время и идентификаторы передаются через `TimerContext`, побочные эффекты
  возвращаются как `TimerEffect`, а не выполняются внутри ядра.
- `Selenite/Engine` – связь ядра с приложением: `TimerEngine` владеет
  состоянием, `EffectRunner` последовательно выполняет эффекты.
- `Selenite/Services` – уведомления и сохранение снимков состояния;
  `Selenite/Features` – SwiftUI-интерфейс. Сохраняй существующее владение
  состоянием через Observation и environment.

## Изменения

- Решай поставленную задачу; не добавляй функции и не рефактори соседний
  код без необходимости. Сохраняй чужие незавершённые изменения.
- Соблюдай Swift 6 strict concurrency. У приложения включены
  Approachable Concurrency и default isolation `MainActor`;
  проверяй изоляцию отдельно для пакета и тестов.
- Не обходи ошибки конкурентности через `@unchecked Sendable`,
  `nonisolated(unsafe)` или ослабление настроек компилятора.
  Учитывай отмену задач, повторные вызовы и жизненный цикл приложения.
- Сохраняй поддержку iOS 18; новые API используй с проверкой доступности.
  Незнакомые и зависящие от версии API проверяй по документации Apple.

## Проверка

- Для изменений ядра запускай из корня репозитория:
  `swift test --package-path Packages/MyLibrary`.
- Для изменений приложения проверяй сборку схемы `Selenite`;
  связанные тесты `SeleniteTests` запускай на доступном iOS Simulator.
- Используй существующий Swift Testing. Для исправления ошибки добавляй
  проверку её сценария; объём проверок соразмеряй с изменением.
- Перед завершением проверь diff. Кратко сообщи, что изменено,
  какие проверки выполнены и что осталось непроверенным.

## Субагенты

- Сам делегируй объёмное исследование встроенному `explorer`, когда это
  разгружает основной контекст; независимые части реализации – `worker`.
- Маленькие и тесно связанные задачи выполняй сам. При делегировании
  задавай границы работы; не поручай одновременную правку одних файлов.
- Перед завершением существенных изменений кода поручай отдельному
  субагенту независимое ревью без редактирования файлов. Проверять:
  корректность, concurrency, владение состоянием, порядок эффектов
  и регрессии. Если настроен `ios_reviewer`, используй его.
- Дождись результатов, проверь замечания и исправь подтверждённые ошибки.
  Итоговую интеграцию и проверку выполняет основной агент.
- Если субагенты недоступны, выполни проверку сам и укажи это в результате.
